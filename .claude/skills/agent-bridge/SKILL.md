Инструмент живёт в `.ai/` этого проекта (bash CLI `.ai/bin/agent` + Node
внутри). Полные правила «когда делегировать» — `.ai/docs/workflow.md`
(NEVER/ASK/ALWAYS, критерии ресёрч vs код). Здесь — только механика вызова.

## Асинхронная задача (обычный случай)

```bash
.ai/bin/agent start --task <slug> --repo <path> --prompt "..."   # вернёт jobId сразу
.ai/bin/agent wait <jobId>                                        # ОТДЕЛЬНЫМ Bash с run_in_background: true
.ai/bin/agent result <jobId>                                      # после уведомления
```

Без шага `wait` в фоновом `Bash`-вызове уведомление о завершении не
придёт — `start` отсоединён (`nohup`), харнесс о нём не знает.

Для кодовых задач добавляй `--worktree` (изоляция в отдельной ветке) и
`--verify "<cmd>"` (тесты/typecheck после агента — вердикт в `agent status`,
сырой вывод не засоряет контекст). После `verify: passed` всегда сверяй
`changedFiles` в `agent status` — пустой дифф при passed значит, что агент
ничего не менял.

## Живой диалог (агент застрял на вопросе)

Если задача запущена с `--interactive`, она не завершается после первого
ответа — процесс остаётся открытым и ждёт следующую реплику:

```bash
.ai/bin/agent start --task <slug> --repo <path> --interactive --prompt "..."
.ai/bin/agent tail <jobId>              # смотришь, что агент написал/спросил
.ai/bin/agent talk <jobId> "да, ставь pdfkit"   # реплика без ожидания
```

`talk` не создаёт новую задачу и не ждёт ответа — просто пишет реплику
в уже работающий процесс. Ответ смотри следующим `tail`. Сейчас
поддерживается только `--runner opencode` (дефолт); для остальных runner
`start --interactive` откажет.

Если канал недоступен (`agent status` покажет `interactiveDegraded`) —
сессия молча работает как обычная асинхронная задача: используй `send`.

## Продолжить завершённую сессию новой репликой

```bash
.ai/bin/agent send <jobId> "новые вводные"   # новая задача, тот же sessionId
```

В отличие от `talk` — это отдельная фоновая задача (новый jobId, свой
`wait`), для случая, когда предыдущая уже завершилась.

## Если задача застряла

`.ai/bin/agent tail <jobId>` — что агент уже написал (стримится в
`out.jsonl`, не одним куском в конце). Признак реального зависания — не
«ждёт подтверждения» (headless-режим их не спрашивает), а лог не растёт
намного дольше разумного при живом `pid`. Тогда `agent kill <jobId>` и
перезапуск с уточнённым промптом.

Полный список команд: `.ai/bin/agent --help`.
